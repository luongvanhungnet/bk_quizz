BÁO CÁO CÔNG NGHỆ SỬ DỤNG TRONG DỰ ÁN BKQUIZ
Ngày lập báo cáo: 25/08/2026

======================================================================
1. TỔNG QUAN HỆ THỐNG
======================================================================

BKQuiz là nền tảng tạo, quản lý, chia sẻ và làm bài quiz. Hệ thống được
chia thành ba ứng dụng chính:

1. Frontend: giao diện web dành cho người học, người tạo quiz và quản trị.
2. Backend: quản lý nghiệp vụ, xác thực, dữ liệu quiz, lớp học, bài làm,
   công việc nền và tích hợp với dịch vụ RAG.
3. RAG service: xử lý tài liệu, tạo chỉ mục tìm kiếm, truy hồi kiến thức,
   gọi mô hình AI và sinh quiz có trích dẫn nguồn.

Luồng tổng quát:

Trình duyệt React
    -> REST/WebSocket tới Spring Boot
    -> PostgreSQL và kho tệp
    -> API nội bộ tới FastAPI RAG
    -> SQLite + FAISS + Redis/Celery
    -> Gemini hoặc Ollama Qwen

3. BACKEND NGHIỆP VỤ
======================================================================

Ngôn ngữ và framework:
- Java 17: ngôn ngữ triển khai backend.
- Spring Boot 4.1.0: nền tảng chính để cấu hình và vận hành ứng dụng.
- Maven/Maven Wrapper: quản lý dependency, build và chạy kiểm thử.

API và xử lý request:
- Spring Web MVC: xây dựng REST API và xử lý multipart upload.
- Bean Validation: kiểm tra dữ liệu request và ràng buộc đầu vào.
- Jackson: chuyển đổi JSON, dùng UTC và UTF-8 trong giao tiếp API.
- Springdoc OpenAPI 3.0.0: sinh OpenAPI tại /api/openapi.json và Swagger UI
  tại /api/docs.

Các miền nghiệp vụ chính trong backend:
- Người dùng và xác thực.
- Topic, nguồn tài liệu và chunk nguồn.
- Quiz, câu hỏi, lựa chọn, đáp án và citation.
- Attempt, snapshot câu hỏi, lưu tiến trình và chấm điểm.
- Classroom, assignment, chat và chia sẻ tài nguyên.
- Community/Explore, thông báo, quản trị và kiểm tra trạng thái hệ thống.
- Job nền cho xử lý tài liệu và sinh quiz theo batch.

Truy cập dữ liệu:
- Spring Data JPA: repository và truy vấn dữ liệu nghiệp vụ.
- Hibernate ORM: ánh xạ entity Java với PostgreSQL.
- HikariCP: connection pool; cấu hình local tối đa 6 kết nối.
- JDBC batching: batch insert/update kích thước 50 và
  reWriteBatchedInserts để giảm round-trip PostgreSQL.
- Flyway: quản lý và kiểm tra migration schema backend.

Bảo mật:
- Spring Security: xác thực và phân quyền endpoint.
- JWT/Jose: access token và refresh token.
- BCrypt: băm mật khẩu, strength mặc định 12.
- Refresh token dùng cookie; XSRF token được cấu hình để chống CSRF.
- Phân quyền theo owner, thành viên lớp và vai trò Admin.
- API nội bộ Spring-RAG dùng internal API key và truyền X-User-Id,
  X-Request-Id để cô lập tenant và truy vết.

Tác vụ nền:
- JobWorker của Spring xử lý job lưu trong PostgreSQL.
- Worker dùng polling, lease, heartbeat, retry và availableAt.
- Quiz generation có checkpoint, chia batch, retry có trì hoãn và commit
  nguyên tử sau khi đủ điều kiện.
- Timeline job được lưu bền vững trong PostgreSQL và frontend đọc theo
  cursor.

Realtime:
- Spring WebSocket và STOMP: chat lớp học và sự kiện chia sẻ tài nguyên.

Tích hợp AI trong backend:
- Spring AI 2.0.0 và Google GenAI starter có trong dependency.
- Luồng sinh quiz thực tế đi qua RAG service để bảo đảm retrieval,
  citation, Cognitive Level và provider fallback được quản lý tập trung.

Xử lý tệp và tài liệu tại backend:
- Apache Tika 3.2.3: nhận dạng và xử lý metadata/nội dung tệp.
- Apache POI 5.4.1: hỗ trợ tài liệu Microsoft Office.
- OpenPDF 2.0.4: chức năng liên quan tới PDF.
- AWS SDK for Java 2.34.0: giao tiếp kho lưu trữ tương thích S3.
- Lưu trữ local là mặc định; MinIO/S3 là lựa chọn cấu hình.
- ClamAV là lựa chọn quét virus cho tệp upload.

Email:
- Resend HTTP API được cấu hình để gửi email khi có API key.

Quan sát hệ thống:
- Spring Boot Actuator: health, info và metrics.
- Micrometer/Prometheus endpoint: xuất metric cho hệ thống giám sát.
- Trace ID được đưa vào log để liên kết lỗi frontend, backend và RAG.

Kiểm thử backend:
- JUnit Jupiter: framework unit/integration test.

- JaCoCo: đo độ bao phủ mã nguồn.

4. CƠ SỞ DỮ LIỆU VÀ LƯU TRỮ
======================================================================

PostgreSQL 16 và pgvector:
- Image triển khai: pgvector/pgvector:pg16.
- Là nguồn sự thật nghiệp vụ cho user, topic, source, quiz, question,
  citation, attempt, classroom, job và timeline.
- pgvector có sẵn trong image để hỗ trợ dữ liệu vector khi cần ở tầng
  PostgreSQL; chỉ mục tìm kiếm RAG chính hiện được quản lý bằng FAISS.
- Flyway quản lý schema và Hibernate chạy ở chế độ validate.

SQLite:
- RAG service dùng SQLite qua SQLAlchemy làm kho metadata cục bộ cho
  document, chunk và indexing job.
- Alembic quản lý migration của SQLite.
- Chế độ WAL, transaction ngắn và các index dành cho job giúp giảm khóa
  ghi trong topology một máy.

FAISS:
- faiss-cpu 1.14.3 lưu và tìm kiếm vector embedding.
- Index được tách theo tenant/user và có manifest/fingerprint để nhận biết
  thay đổi model hoặc phiên bản extraction.

Redis:
- Redis 7.4 Alpine trong Docker.
- Là broker cho Celery, distributed lock của FAISS index, heartbeat worker,
  rate limiting, dedupe và một số cache vận hành.
- Production yêu cầu Redis cho thao tác index phân tán; development có thể
  dùng local lock theo cấu hình.

Kho tệp:
- Docker volume/local filesystem là mặc định cho file upload và index.
- MinIO là kho object tương thích S3 tùy chọn, chạy bằng profile s3.
- Không đưa file, vector index hoặc dữ liệu nghiệp vụ vào frontend.

5. RAG SERVICE VÀ TRÍ TUỆ NHÂN TẠO
======================================================================

Ngôn ngữ và web framework:
- Python 3.x.
- FastAPI 0.139.2 và Starlette 1.3.1: API bất đồng bộ.
- Uvicorn 0.51.0: ASGI server.
- Pydantic Settings 2.14.2: schema request/response và cấu hình môi trường.
- python-multipart: nhận file upload multipart.
- HTTPX 0.28.1: HTTP client bất đồng bộ và streaming.

Mô hình embedding và tìm kiếm:
- sentence-transformers 5.6.0 trong môi trường phát triển/model export.
- ONNX Runtime 1.27.0 trong runtime production.
- Embedding backend mặc định ONNX, precision INT8, giúp giảm RAM và latency.
- tokenizers và Hugging Face Hub: tokenizer và phân phối model.
- NumPy 2.4.6: xử lý vector và ma trận.
- FAISS CPU: vector similarity search.
- rank-bm25 0.2.2: lexical search BM25.
- Hybrid retrieval kết hợp vector search và BM25, sau đó fusion/rerank theo
  cấu hình.
- Cache retrieval và fingerprint index tránh tính lại dữ liệu không đổi.

Mô hình sinh nội dung:
- Google GenAI SDK 2.14.0: gọi Gemini bằng API key.
- google-auth 2.56.2: gọi Gemini OAuth/ADC và tự refresh credential.
- Thứ tự fallback sinh quiz:
  1. Gemini API key.
  2. Gemini OAuth.
  3. Ollama chạy Qwen local.
- Gemini được chia tối đa 10 câu mỗi request.
- Ollama mặc định dùng qwen3:1.7b, tắt thinking, tối đa 2 câu/request,
  context 4096 và output budget 2400 token.
- Các provider dùng chung structured output, question plan, Cognitive Level
  và bộ kiểm tra citation.

Cognitive Level và kiểm tra chất lượng:
- Câu hỏi AI dùng L1 đến L5 thay cho Easy/Medium/Hard.
- Mỗi câu có số khái niệm, số bước suy luận, cờ tình huống mới, câu trả lời
  trực tiếp và yêu cầu so sánh.
- Complexity Score được tính theo công thức K + 2R + T + C.
- Lỗi chất lượng như citation thiếu, Cognitive chưa đạt hoặc câu gần trùng
  được lưu thành warning; lỗi cấu trúc không thể làm bài vẫn là error.

Citation và grounding:
- Citation được kiểm tra theo exact match, normalized match, lexical match
  và semantic match.
- Quote gần đúng phải được ánh xạ về span nguyên văn trong chunk trước khi
  lưu; metadata nguồn lấy từ RAG index, không tin dữ liệu AI tự khai báo.
- Tenant isolation bảo đảm chỉ dùng document thuộc đúng người dùng và danh
  sách nguồn được chọn.

Xử lý tài liệu:
- PyMuPDF 1.28.0: đọc PDF theo page, block, span và bounding box.
- python-docx 1.2.0: đọc DOCX.
- python-pptx 1.0.2: đọc PPTX và metadata slide.
- TXT/Markdown được xử lý như nội dung văn bản.
- Pipeline gồm parse, chunk, embedding, index và đồng bộ chunk metadata.
- PDF toán học dùng layout extraction và có Gemini Vision fallback cho vùng
  công thức khó nhận dạng.
- Nội dung công thức được chuẩn hóa sang LaTeX; lỗi nhận dạng không làm mất
  toàn bộ tài liệu mà tạo cảnh báo PARTIAL/FAILED phù hợp.

Job xử lý tài liệu:
- Celery 5.5.3: chạy indexing job và các tác vụ phục hồi.
- Redis là message broker.
- Celery worker dùng pool solo, concurrency 1 để tương thích Windows,
  SQLite và FAISS single-host.
- Celery Beat chỉ lập lịch recovery/reconciliation; worker mới trực tiếp
  xử lý tài liệu.
- Heartbeat Redis giúp API biết worker còn hoạt động hay không.

Streaming và khả năng phục hồi:
- RAG trả NDJSON streaming cho tiến trình sinh quiz và trợ lý AI.
- Event gồm provider, batch, part, stage, warning, lỗi và kết quả.
- Checkpoint giữ output có cấu trúc để không gọi lại AI khi bước hậu kiểm
  hoặc kết nối backend bị gián đoạn.
- Circuit breaker được áp dụng cho provider fallback phù hợp; Gemini API key
  vẫn được thử đầu tiên ở mỗi batch theo chính sách hiện tại.

Quan sát và kiểm thử RAG:
- prometheus-client 0.22.1: metric API, provider, retrieval và worker.
- pytest: unit, integration và regression test.
- Ruff: lint/format checks.
- mypy: static type checking.
- pip-audit và pip check: kiểm tra dependency.
- OpenAPI drift check: bảo đảm tài liệu API đồng bộ với code.

6. GIAO TIẾP GIỮA CÁC THÀNH PHẦN
======================================================================

Frontend -> Backend:
- HTTPS/HTTP REST với JSON.
- Multipart/form-data cho upload tài liệu.
- WebSocket/STOMP cho chat và sự kiện lớp học.
- NDJSON/ReadableStream cho phản hồi AI streaming qua backend.
- JWT, refresh cookie và XSRF token cho phiên đăng nhập.

Backend -> RAG:
- REST API nội bộ dùng JSON hoặc multipart.
- NDJSON stream cho timeline sinh quiz và chat AI.
- X-Internal-API-Key để xác thực dịch vụ.
- X-User-Id để cô lập tenant.
- X-Request-Id để correlation log và tra cứu lỗi.
- Capabilities endpoint để phát hiện lệch contract giữa Spring và RAG.

RAG -> AI provider:
- Google GenAI SDK cho API key.
- Google AuthorizedSession/OAuth ADC cho OAuth.
- HTTP API của Ollama cho Qwen local.
